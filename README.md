# Приёмка медицинских документов

`medintake` — внутренний сервис приёмки пакетов, которые уходят в страховые организации по ОМС и ДМС. Он проверяет структуру, полис, СНИЛС, даты, диагнозы по МКБ-10 и уникальность внутри сессии, затем отдаёт отчёт.

Это не формат реестра счетов ТФОМС и не шлюз информационного обмена со страховой. Сюда попадает пакет до выгрузки, чтобы ошибки ловились у себя, а не ответом страховой.

За одну сессию принимается до 10 000 файлов. Проверка идёт через общую библиотеку: из командной строки синхронно, через API — фоновой очередью на SQLite.

## Что проверяется

| Слой | Зачем |
| --- | --- |
| Приём файла | файл читается, не превышает лимит размера, XML разбирается без внешних сущностей |
| XSD | состав документа, пол, формат СНИЛС, шаблон МКБ-10, дата, тип страхования, код страховой, номер полиса |
| Бизнес-правила | пустые обязательные поля, контрольное число СНИЛС, даты и возраст, 16 цифр полиса ОМС, один основной диагноз, повтор кода МКБ-10 |
| Справочник МКБ-10 | код есть в загруженном справочнике |
| Сессия | `DocumentId` не повторяется, содержимое файлов не совпадает |

Ошибка XSD не отменяет остальные проверки того же файла: отправитель получает список за один проход. Предупреждение не отклоняет документ.

Пока справочник МКБ-10 неполный, неизвестный код — предупреждение (`MEDINTAKE_ICD10_MODE=warn`). Когда аналитик кладёт полную выгрузку НСИ, режим переключают на `error`.

## Состав

```
medintake/
  api.py            REST
  batch.py          сессия и уникальность между файлами
  checks.py         реестр кодов проверок
  cli.py            командная строка
  jobs.py           очередь SQLite и фоновый обработчик
  rules.py          бизнес-правила
  validator.py      чтение файла и XSD
  schemas/          XSD внутреннего документа
  data/icd10.csv    справочник МКБ-10
example/            образцы, в том числе чистый пакет example/package
tests/
```

Реестр проверок — контракт для аналитика и QA. Реализация правила живёт в `rules.py`. Оба места меняются вместе.

## Установка

Нужен Python 3.11 или новее.

```powershell
py -3 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
```

Параметры сервиса — в `.env.example`. Файл `.env` в репозиторий не кладётся.

## Командная строка

Чистый пакет:

```powershell
python -m medintake.cli example/package
```

Один файл, свой режим справочника, отчёт:

```powershell
python -m medintake.cli example/valid.xml --format json --output report.json
python -m medintake.cli example/ --icd10-mode error --format csv --output report.csv
```

Каталог читается без вложенных папок, только `*.xml`. В отчёте путь к файлу такой, каким он передан в команде: для `example` это `example\invalid.xml`, а не полный путь на диске. Отчёт CLI уходит аналитику и в заявки, и раскладке папок машины оператора в нём не место. В отчёте API стоит только исходное имя загруженного файла.

```powershell
python -m medintake.cli example\invalid.xml example\empty_document_id.xml
```

```text
[FAILED] example\invalid.xml
  [ERROR] XSD_VALIDATION: Поле «Gender»: значение «X» недопустимо. Допустимые значения: «M», «F». (/MedicalDocument/Patient/Gender)
  [ERROR] XSD_VALIDATION: Поле «Snils»: значение «112-233-445» не соответствует требуемому формату. (/MedicalDocument/Patient/Snils)
  [ERROR] XSD_VALIDATION: Поле «Icd10Code»: значение «9.9» не соответствует требуемому формату. (/MedicalDocument/Diagnosis/Icd10Code)
[FAILED] example\empty_document_id.xml
  [ERROR] EMPTY_REQUIRED_FIELD: Обязательное поле «Идентификатор документа» не заполнено. (/MedicalDocument/DocumentId)
Итого: 0/2 без ошибок, ошибок 4, предупреждений 0.
```

Код выхода: `0` — нет ошибок, `1` — в документах есть ошибки, `2` — сессия не принята (нет файлов, нет схемы, пакет больше лимита). Предупреждения код выхода не меняют.

Для большого пакета нужен JSON или CSV. Текстовый отчёт по сессии больше 20 файлов печатает только файлы с замечаниями и итог.

## API

```powershell
python -m medintake.api
```

По умолчанию сервис слушает `127.0.0.1:8080`. Описание методов — `/docs`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Обработчик очереди и база живы, без токена. `503`, если нет |
| GET | `/api/v1/checks` | Реестр проверок |
| POST | `/api/v1/batches` | Загрузка XML, ответ `202` |
| POST | `/api/v1/batches/directory` | Каталог внутри `MEDINTAKE_INBOX_ROOT` |
| GET | `/api/v1/batches` | Последние сессии |
| GET | `/api/v1/batches/{id}` | Статус: `queued`, `running`, `completed`, `failed` |
| GET | `/api/v1/batches/{id}/report?format=json` | Отчёт, когда сессия завершена |
| GET | `/api/v1/batches/{id}/report?format=csv` | Тот же отчёт для Excel |

Загрузка:

```powershell
curl.exe -F "files=@example/package/doc_001.xml" -F "files=@example/package/doc_002.xml" http://127.0.0.1:8080/api/v1/batches
```

Каталог на диске (путь относительный, выйти выше корня приёма нельзя):

```powershell
curl.exe -H "Content-Type: application/json" -d "{\"directory\":\"2026-10-22/smo-77001\"}" http://127.0.0.1:8080/api/v1/batches/directory
```

Если задан `MEDINTAKE_API_TOKEN`, методы `/api/v1/*` требуют `Authorization: Bearer <токен>`. `/health` остаётся открытым для проверки процесса. На стенде токен задаётся всегда, пустое значение допустимо только локально.

Пока сессия не завершена, отчёт отвечает `409`. После перезапуска сессия, которую не успели досчитать, переводится в `failed`, а не остаётся вечно в `running`.

Очередь одна, обработчик один. Для этой нагрузки отдельный брокер не нужен: 10 000 небольших XML укладываются в процесс, состояние лежит в `var/jobs.sqlite3`. Поэтому сервис запускается одним процессом uvicorn, без `--workers`: второй процесс при старте пометит чужие сессии как прерванные.

Сбой базы не останавливает обработчик: он пишет ошибку в журнал и повторяет попытку. Если обработчик всё же остановился, `/health` отвечает `503`, и оркестратор перезапускает контейнер.

Загрузка в одном запросе принимает до `MEDINTAKE_MAX_FILES` файлов. Общий размер тела запроса ограничивается на обратном прокси (`client_max_body_size` в nginx), сервис ограничивает только размер каждого файла.

Принятые XML удаляются, как только отчёт построен. В каталоге сессии остаются `report.json` и `report.csv`. Срок хранения отчётов определяет регламент обработки персональных данных, автоматической очистки сейчас нет.

## Документ

```xml
<MedicalDocument version="1.1">
  <DocumentId>DOC-2026-001</DocumentId>
  <DocumentDate>2026-10-01</DocumentDate>
  <InsuranceType>OMS</InsuranceType>
  <InsurerCode>77001</InsurerCode>
  <PolicyNumber>7700123456789012</PolicyNumber>
  <OrganizationCode>ORG-001</OrganizationCode>
  <Patient>
    <LastName>Иванов</LastName>
    <FirstName>Иван</FirstName>
    <BirthDate>1985-03-20</BirthDate>
    <Gender>M</Gender>
    <Snils>112-233-445 95</Snils>
  </Patient>
  <Diagnosis>
    <Icd10Code>J06.9</Icd10Code>
    <Description>Острая инфекция верхних дыхательных путей</Description>
    <IsPrimary>true</IsPrimary>
  </Diagnosis>
</MedicalDocument>
```

`InsuranceType` — `OMS` или `DMS`. Для ОМС номер полиса — 16 цифр, для ДМС — строка из букв, цифр и дефиса длиной 6–30. Код страховой — 5 цифр. Дата — `ГГГГ-ММ-ДД` без часового пояса. Пол — `M` или `F`. СНИЛС — `123-456-789 01`, контрольное число считается отдельно от формата.

Дата документа в будущем отклоняется. Дата старше `MEDINTAKE_MAX_DOCUMENT_AGE_DAYS` (по умолчанию 366) даёт предупреждение `STALE_DOCUMENT_DATE`. «Сегодня» считается в поясе `MEDINTAKE_TIMEZONE` (по умолчанию `Europe/Moscow`), а не в поясе сервера: в контейнере UTC, и документ от сегодняшнего числа после полуночи по Москве иначе был бы «из будущего».

Контрольное число СНИЛС проверяется для номеров больше `001-001-998`, как в правилах ПФР.

## Отчёт

JSON содержит блок `context`: версию сервиса, дату приёма, часовой пояс и режим справочника МКБ-10. По нему через месяц можно объяснить, почему документ получил именно такие замечания.

В CSV имя файла и `DocumentId` приходят от отправителя. Значение, которое начинается с `=`, `+`, `-` или `@`, получает префикс `'`, чтобы Excel не исполнил его как формулу.

## Справочник МКБ-10

Файл `medintake/data/icd10.csv`, колонки `code,title`, UTF-8. Excel можно сохранять с BOM. Повтор кода в файле — ошибка старта проверки, а не тихое перезаписывание.

Аналитик подменяет файл полной выгрузкой и ставит `MEDINTAKE_ICD10_MODE=error`. Путь к другому файлу — `MEDINTAKE_ICD10_PATH`.

## Как добавить проверку

1. Описать код, уровень и смысл в `checks.py`. Код сразу появится в `GET /api/v1/checks`.
2. Добавить функцию в `rules.py` и включить её в кортеж `_CHECKS`.
3. Покрыть случаем в `tests/`, в том числе соседним документом, который проходить должен.

Правила между файлами (уникальность) остаются в `batch.py`: у одного документа нет всей сессии.

## Журнал

В журнал пишутся номер сессии, число файлов и итог. Текст документа, СНИЛС и ФИО туда не попадают: они остаются в отчёте, который и так видит оператор.

## Тесты

```powershell
pytest
ruff check .
```

Версии зависимостей для CI и Docker зафиксированы в `requirements.txt` и подключаются как constraints: `pip install -c requirements.txt -e ".[dev]"`. Диапазоны допустимых версий указаны в `pyproject.toml`.

Дата приёма в тестах правил зафиксирована. Образцы в `example/` датированы 2026-10-01, поэтому на более позднем календаре у них может появиться предупреждение о возрасте документа — на отклонение это не влияет.

## Сборка

```powershell
docker build -t medintake .
docker run --rm -p 8080:8080 -e MEDINTAKE_API_TOKEN=change-me -v medintake-data:/data medintake
```

Процесс в контейнере работает не от root (uid 10001). Состояние контейнера Docker берёт из `HEALTHCHECK` по `/health`.
